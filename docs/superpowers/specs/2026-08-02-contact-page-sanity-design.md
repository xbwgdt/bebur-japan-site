# 联系页 Sanity 可编辑化与可读性改造设计

日期：2026-08-02

## 目标

修复 `/contact` 右侧“お問い合わせの流れ”卡片文字与背景对比度不足的问题，消除两个邮件按钮的功能重复，并让联系页主要文字、配色、字号和字体能够在 Sanity 中安全修改。

## 已确认的交互

- 左侧主按钮显示 `電話で相談`，链接固定为 `tel:080-5189-8663`。
- 左侧次按钮显示 `メールでお問い合わせ`，继续打开写信界面并发送至 `info@newtree-i.com`。
- 默认字体使用标准黑体。
- 已确认的公司名称、地址、电话和邮箱继续使用受保护的正式联系方式，不允许通过普通内容编辑误改。

## 数据模型

在单例 `siteSettings` 的“联系信息”分组中新增 `contactPage` 对象，包含：

### 左侧联系卡片

- `label`：代理店小标题。
- `description`：公司服务说明。
- `phoneActionLabel`：电话按钮文字。
- `emailActionLabel`：邮件按钮文字。
- `style`：卡片显示预设。

公司名称、邮编、地址、电话和邮箱仍读取现有受保护字段，不在 `contactPage` 内重复保存。

### 右侧咨询流程卡片

- `eyebrow`：英文小标题。
- `title`：主标题。
- `steps`：咨询流程步骤数组，默认三项。
- `linkLabel`：底部邮件链接文字。
- `style`：卡片显示预设。

### 安全样式预设

不允许录入任意 CSS、任意颜色值或任意字体名称。Sanity 只提供下拉或单选预设：

- 配色：白底深蓝字、深蓝底白字、浅蓝底深蓝字。
- 字号：小、标准、大、特大。
- 字体：标准黑体、明朝体、等宽字体。

正式默认值为标准黑体；右侧卡片使用深蓝底、白色正文与亮青色强调线。所有组合必须维持清晰的文字对比度。

## 前台渲染

联系页统一从已解析的 `publicSiteSettings.contactPage` 读取内容。普通联系页与存在 CMS 页面内容时追加的联系模块使用同一份组件与设置，避免两套硬编码内容再次发生偏差。

Sanity 数据在进入组件前经过白名单解析：

- 无效文字、空值或超长内容回退到本地默认值。
- 未知配色、字号或字体回退到已验证的默认预设。
- 电话和邮箱链接由受保护的正式联系方式生成，编辑人员只能修改按钮显示文字，不能改变目标地址。
- 流程步骤为空或无效时恢复默认三步流程。

## 默认内容

- 电话按钮：`電話で相談`
- 邮件按钮：`メールでお問い合わせ`
- 咨询流程小标题：`INQUIRY GUIDE`
- 咨询流程标题：`お問い合わせの流れ`
- 流程步骤：
  1. `製品・用途を確認`
  2. `電話またはメールで相談`
  3. `仕様・見積もりをご案内`
- 底部链接：`メールで問い合わせ`

## 可访问性与响应式要求

- 右侧卡片标题、正文、步骤和链接在深蓝背景上均使用高对比度浅色。
- 焦点、悬停和键盘操作状态必须清晰可见。
- 按钮维持可触控高度，电话和邮件链接保留准确的可访问名称。
- 桌面端保持双栏结构；窄屏端改为单栏且不出现文字溢出。

## 测试与验收

- 测试 Sanity schema 中所有新增字段和固定样式预设。
- 测试查询包含 `contactPage`，解析器只接受白名单值并正确回退。
- 测试电话按钮使用 `tel:080-5189-8663`，邮件按钮使用正式邮箱的 `mailto:`。
- 测试两种联系页渲染路径均使用相同内容和样式。
- 执行单元测试、类型检查和生产构建。
- 在桌面与手机宽度下目视检查联系页，确认右侧卡片文字清晰、按钮不重复、布局无溢出。

## 不在本次范围内

- 不开放正式公司联系方式的任意修改。
- 不允许编辑人员输入原始 CSS 或 JavaScript。
- 不重做联系页整体结构，也不改变网站其他页面的设计。
