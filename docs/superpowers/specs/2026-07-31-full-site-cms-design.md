# Bebur Japan 全站模块化内容后台设计

## 目标

将现有 112 个日文内容页面升级为 Sanity 驱动的模块化后台。管理员可在中文 Sanity Studio 中编辑每页文字、图片、按钮与 SEO，并通过预设的颜色、字号、对齐、间距和桌面单行选项控制展示；发布后自动触发 Cloudflare Pages 更新。

## 边界

- 覆盖首页、产品、新闻、企业信息、行业应用及其现有内容页面。
- 可编辑：文本、富文本正文、图片、按钮、卡片、表格数据、SEO、模块顺序、预设视觉样式。
- 样式只提供受控预设；不提供任意 CSS、任意 JavaScript 或自由尺寸输入。
- 保留当前日文网站路由、移动端适配、联系信息与 Cloudflare/Sanity 自动发布链路。
- 代码修复、域名、访问权限、构建配置和安全策略仍由开发维护，不开放为 CMS 字段。

## 内容模型

### 站点设置

扩展现有 `siteSettings`：全站导航、页脚、默认 SEO、全局品牌预设与首页模块内容。

### 页面文档

新增统一 `page` 文档，使用稳定的现有路由作为 slug。它包含页面标题、SEO、模块数组和发布状态。已有产品、新闻等专用文档保留，并在需要时由页面模块引用。

### 可复用模块

- 主视觉：标签、标题、摘要、背景图、按钮、标题预设样式。
- 富文本内容：小标题、正文、图片、列表、引用。
- 图片图集：图片、替代文字、展示比例与预设布局。
- 卡片网格：标题、说明、图片、链接及预设列数。
- 数据表：表头与行项目，适用于产品规格。
- CTA：标题、说明、按钮和预设主题色。
- 专用引用模块：产品列表、新闻列表、关联内容。

每个模块的样式字段限定为枚举值，例如颜色 `brand/blue/red/neutral`、字号 `sm/md/lg/xl`、对齐 `left/center`、间距 `compact/normal/spacious`、桌面标题 `wrap/nowrap`。

## 前台渲染

前台建立模块渲染器，将 Sanity 模块类型映射为现有 React 组件及 CSS 预设 class。对于每个模块，未填写的样式回退到当前页面的视觉默认值。当前页面路由保持不变；在迁移完成前，内容数据缺失时继续使用已确认的本地内容作为回退，避免页面空白。

## 后台体验与发布

Studio 保持中文界面。页面编辑入口按“首页 / 页面内容 / 产品 / 新闻 / 网站设置”组织；模块显示中文标题、用途提示、图片替代文字与 SEO 校验。管理员拥有直接发布权限。Sanity 的现有 webhook 在创建、更新、删除时调用 Cloudflare Pages deploy hook，因此发布内容后自动重新构建静态站点。

## 迁移策略

1. 先建立模块 schema、受控样式预设和前台渲染器。
2. 迁移首页与代表性页面，验证后台编辑、预览、发布与移动端。
3. 批量转换其余页面，保持 112 页现有文本、图片与路由一致。
4. 用路由清单、内容审计和静态构建验证没有漏页或空白页。
5. 最后移除不再需要的本地内容回退，仅保留必要的故障兜底。

## 验收标准

1. 112 个页面均可在 Sanity 中编辑主要文字与图片。
2. 首页与普通页面可在后台选择受控的颜色、字号、对齐、间距及桌面单行样式。
3. 管理员发布后，Cloudflare 自动构建并公开新内容。
4. 全部现有路由、联系信息、日文 SEO、图片替代文字和手机端展示保持有效。
5. 自动测试覆盖 schema、模块映射、路由完整性、样式预设和发布配置。

## 风险控制

模块化迁移会分阶段进行，每阶段都保留内容回退并验证静态输出。受控预设避免管理员误填 CSS 造成布局破坏；图片字段强制替代文字以维持无障碍与搜索质量。
